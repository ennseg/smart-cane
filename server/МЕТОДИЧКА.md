## 1. Что это и из чего состоит

```
 ESP32 на трости ──HTTP(S) + JSON──► сервер (FastAPI) ──► SQLite
                  ◄── ack, cmd, cfg ──     │
                                           ▼
                                  Telegram-бот (aiogram) ◄──► сопровождающие в Telegram
```

- **Сервер** принимает пакеты устройства на `POST /api/v1/telemetry`, проверяет токен и подпись,
  сохраняет данные и решает, кому и что отправить.
- **Бот** живёт в том же процессе и отвечает сопровождающим на команды `/where`, `/status`, `/history` и др.
- **Симулятор** (`simulator/`) притворяется прошивкой ESP32: шлёт такие же пакеты и с такой же подписью.
  Благодаря ему всё проверяется без железа.
- **Режим DRY_RUN** позволяет обойтись и без Telegram: сообщения бота пишутся в лог, а «писать боту»
  можно утилитой `devchat`.

## 2. Установка Python и зависимостей

### Python

Нужен **Python 3.11 или новее** (проверено на 3.12 и 3.14).

- **Windows:** скачайте установщик с <https://www.python.org/downloads/> и при установке
  отметьте **«Add python.exe to PATH»**. Проверка в PowerShell: `python --version`.
- **Ubuntu/Debian:** `sudo apt install python3 python3-venv python3-pip`. Проверка: `python3 --version`.
- **macOS:** `brew install python@3.12`.

### Зависимости проекта

Все команды выполняются **из корня проекта** (папка, где лежат `pyproject.toml` и `README.md`).

Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
```

> Если PowerShell пишет «выполнение сценариев отключено», один раз выполните
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
```

- `requirements.txt` содержит только то, что нужно для работы сервера (на VPS ставьте его).
- `requirements-dev.txt` добавляет pytest, ruff и black для разработки.

Проверьте, что всё установилось:

```bash
pytest -q          # должно быть: 143 passed
```

## 3. Создание бота через @BotFather

Этот шаг нужен только для работы с настоящим Telegram. Для режима DRY_RUN его можно пропустить.

1. Откройте в Telegram чат с **@BotFather** (у него синяя галочка).
2. Отправьте `/newbot`.
3. Введите отображаемое имя, например `Умная трость`.
4. Введите username бота. Он должен заканчиваться на `bot`, например `smart_cane_itmo_bot`.
5. BotFather пришлёт **токен** вида `7712345678:AAH...`. Это пароль от бота: не публикуйте его
   и не коммитьте в git.
6. По желанию: `/setdescription` (описание), `/setuserpic` (аватар). Меню команд настраивать
   не нужно: сервер при старте сам регистрирует его через `setMyCommands`.

## 4. Настройка .env

Скопируйте шаблон:

```bash
copy .env.example .env      # Windows
cp .env.example .env        # Linux/macOS
```

Сервер читает `.env` из **текущей папки**, поэтому запускайте его из корня проекта. Любую переменную
можно задать и через окружение. Пустое значение означает «использовать значение по умолчанию».

### Telegram и режимы

| Переменная | По умолчанию | Что означает |
|---|---|---|
| `BOT_TOKEN` | пусто | Токен от @BotFather. Обязателен, если `DRY_RUN=false`. |
| `DRY_RUN` | `false` (в `.env.example` — `true`) | `true`: к Telegram не обращаемся, все сообщения бота пишутся в лог. |
| `DEV_ENDPOINTS` | пусто (= как `DRY_RUN`) | Включает `POST /dev/bot`, через который можно писать боту без Telegram. На боевом сервере держите выключенным. |

### Сервер и база

| Переменная | По умолчанию | Что означает |
|---|---|---|
| `DATABASE_URL` | `sqlite+aiosqlite:///./data/cane.db` | Где лежит база. Папка создаётся сама. Для PostgreSQL: `postgresql+asyncpg://user:pass@host/db` (нужно доустановить `asyncpg`). |
| `HOST` | `0.0.0.0` | На каком интерфейсе слушать. `0.0.0.0` — на всех: это нужно, чтобы ESP32 в локальной сети достучался. |
| `PORT` | `8000` | Порт HTTP. |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`. |

### Приём данных

| Переменная | По умолчанию | Что означает |
|---|---|---|
| `HMAC_REQUIRED` | `true` | Требовать заголовок `X-Signature`. Выключать стоит только для отладки. |
| `DEFAULT_PERIOD_S` | `30` | Период передачи для новых устройств. Сервер сообщает его устройству в `cfg.period_s`. |
| `MAX_BODY_BYTES` | `4096` | Максимальный размер одного пакета в байтах. |
| `BATCH_MAX_PACKETS` | `50` | Максимум пакетов в одном запросе на `/telemetry/batch`. |

### Фоновые проверки

| Переменная | По умолчанию | Что означает |
|---|---|---|
| `SILENCE_PERIODS` | `3` | Тревога «устройство не выходит на связь» срабатывает, если пакетов нет дольше `SILENCE_PERIODS × period_s` (таблица 7). |
| `MONITOR_INTERVAL_S` | `15` | Как часто идёт фоновая проверка (молчание, напоминания SOS, просроченные `/where`). |
| `OUTBOX_POLL_S` | `2` | Как часто проверяется очередь исходящих сообщений. Новые сообщения уходят сразу, без ожидания. |
| `OUTBOX_MAX_ATTEMPTS` | `8` | Сколько раз пытаться доставить сообщение, если Telegram недоступен. |
| `LOCATE_TIMEOUT_S` | `300` | Сколько ждать свежую позицию после `/where`. |

### SOS, антифлуд, привязка, отображение

| Переменная | По умолчанию | Что означает |
|---|---|---|
| `SOS_LIVE_MIN` | `10` | Сколько минут после SOS двигается «живая» точка на карте. |
| `SOS_REMIND_S` / `SOS_REMIND_MAX` | `120` / `3` | Как часто и сколько раз напоминать о SOS, пока никто не нажал «✅ Принял». |
| `BUFFERED_ALERT_MAX_AGE_MIN` | `30` | Досланные с задержкой события старше этого возраста только сохраняются, без уведомления. Исключения: `sos` и `batt_crit`, о них уведомляют всегда. |
| `COOLDOWN_STILL_MIN` | `10` | Не повторять «нет движения» чаще, чем раз в N минут. |
| `COOLDOWN_BATT_LOW_MIN` | `360` | То же для «низкий заряд». |
| `COOLDOWN_BATT_CRIT_MIN` | `60` | То же для «критический разряд». |
| `COOLDOWN_GPS_MIN` | `10` | То же для «пропал GPS». |
| `STILL_DEFAULT_MIN` | `10` | Какое число минут писать в тревоге неподвижности, если устройство не прислало `still_min`. |
| `BIND_MAX_FAILURES` / `BIND_BLOCK_MIN` | `5` / `60` | Защита от подбора кода: после 5 неверных `/bind` подряд блокировка на 60 минут. |
| `INVITE_TTL_H` | `24` | Сколько часов действует код из `/invite`. |
| `HISTORY_LIMIT` | `10` | Сколько точек показывает `/history`. |
| `DISPLAY_TZ` | `Europe/Moscow` | Часовой пояс, в котором показывается время в сообщениях. |
| `MAP_URL_TEMPLATE` | Яндекс.Карты | Шаблон ссылки на карту в `/history`, подстановки `{lat}` и `{lon}`. Вариант для OSM: `https://www.openstreetmap.org/?mlat={lat}&mlon={lon}#map=17/{lat}/{lon}`. |

## 5. Регистрация устройства и код привязки

Каждая трость регистрируется на сервере один раз:

```bash
python -m cane_server.cli add-device cane-01 --name "Трость Ивана" --sim-config sim/cane-01.json
```

- `cane-01` — идентификатор устройства: 1–32 символа, латиница, цифры, `-`, `_`. Это поле `dev` в пакетах.
- `--name` — как трость будет называться в сообщениях бота.
- `--period 30` — период передачи в секундах (необязательно). Для демонстрации удобно 5.
- `--server-url http://192.168.1.50:8000` — адрес сервера, который попадёт в `secrets.h` и конфиг симулятора.
- `--sim-config путь.json` — сохранить данные для симулятора.

Пример вывода:

```
Устройство «Трость Ивана» (cane-01) зарегистрировано.

КОД ПРИВЯЗКИ для паспорта изделия (одноразовый):
    HZQS-75PE

Данные для прошивки (показываются ОДИН раз, сохраните их):
    X-Device-Token: 6t8N5Rge9qSNbTeZyN1f1PvG_d0HICZP
    HMAC secret:    a073f9961a81c9c1e3d5fd5cb96c9938ffc8cc37a46f9f39a19bdf47780c1c6d

Фрагмент secrets.h для прошивки ESP32:
#pragma once
#define CANE_DEVICE_ID   "cane-01"
#define CANE_TOKEN       "6t8N5Rge9qSNbTeZyN1f1PvG_d0HICZP"
#define CANE_HMAC_SECRET "a073f9961a81c9c1e3d5fd5cb96c9938ffc8cc37a46f9f39a19bdf47780c1c6d"
#define CANE_SERVER_URL  "http://127.0.0.1:8000/api/v1/telemetry"
```

- **Код привязки** вписывается в паспорт изделия. Первый сопровождающий отправляет его боту
  командой `/bind`. Код одноразовый.
- **Токен и секрет** передаются разработчику прошивки (файл `secrets.h`, в git его не добавлять).
  В базе хранится только хеш токена, поэтому показать его второй раз невозможно.

Другие команды CLI:

| Команда | Что делает |
|---|---|
| `python -m cane_server.cli list-devices` | Список устройств, число сопровождающих, последний контакт |
| `python -m cane_server.cli new-code cane-01` | Новый одноразовый код привязки (например, если паспорт потерян) |
| `python -m cane_server.cli rotate-token cane-01` | Новый токен и секрет. Старые сразу перестают действовать, прошивку нужно обновить |
| `python -m cane_server.cli set-period cane-01 15` | Изменить период. Устройство получит его в ответе в поле `cfg` |
| `python -m cane_server.cli disable-device cane-01` | Запретить приём данных (ответ 403). Обратная команда — `enable-device` |
| `python -m cane_server.cli init-db` | Создать таблицы. Обычно не нужна: сервер создаёт их сам |

## 6. Запуск сервера

```bash
python -m cane_server
```

Признаки успешного старта (в режиме Telegram):

```
INFO    cane_server.app: Бот подключён к Telegram: @smart_cane_itmo_bot
INFO    cane_server.app: Сервер запущен: DRY_RUN=False, фоновые задачи: outbox, monitor, telegram-polling
INFO    uvicorn.error: Uvicorn running on http://0.0.0.0:8000
```

Проверка в браузере или через curl: `http://127.0.0.1:8000/api/v1/health` должен вернуть `{"status":"ok",...}`.
Интерактивная документация API (Swagger, как springdoc в Spring) открывается по адресу `http://127.0.0.1:8000/docs`.

Остановка: `Ctrl+C`.

### Режим DRY_RUN: всё без Telegram

В `.env` укажите `DRY_RUN=true` (или запустите так: `DRY_RUN=true python -m cane_server` в bash,
`$env:DRY_RUN="true"; python -m cane_server` в PowerShell).

- Сервер не обращается к Telegram, токен не нужен.
- Всё, что бот отправил бы, пишется в лог:

  ```
  INFO telegram.dry_run: [TG → 1001] sendMessage [кнопки: ✅ Принял]:
  🆘 <b>SOS! Трость Ивана просит помощи</b>
  ...
  INFO telegram.dry_run: [TG → 1001] sendLocation 59.959315,30.310752 live=600s
  ```

- «Написать боту» можно утилитой **devchat** (это HTTP-запрос к `POST /dev/bot`). Сообщение
  проходит через тот же диспетчер aiogram, что и настоящее:

  ```bash
  python -m cane_server.devchat 1001 "/bind HZQS-75PE" --name Мария
  python -m cane_server.devchat 1001 "/where"
  python -m cane_server.devchat 1002 --button "sos_ack:5" --name Пётр
  ```

  `1001` — условный chat_id сопровождающего. Ответы бота печатаются сразу. Сообщения, которые
  бот отправляет сам (тревоги), видны в логе сервера.

## 7. Симулятор устройства

Симулятор ведёт себя как прошивка из документа архитектуры:
- шлёт пакеты в формате раздела 5.6 с токеном и подписью HMAC;
- сохраняет `seq` между запусками в файле `*.seq.json`;
- выполняет команду `locate_now` сразу после её получения;
- подчиняется `cfg.period_s`;
- при отсутствии связи копит пакеты в OfflineBuffer и досылает их с `buffered: true`.

```bash
python -m simulator --config sim/cane-01.json --scenario all
```

| Сценарий | Что происходит | Что придёт сопровождающему |
|---|---|---|
| `walk` | Ходьба: плановая позиция каждый период (`--steps N`) | Ничего, позиции только сохраняются. `/where` и `/history` их покажут |
| `gps_loss` | Человек заходит в помещение: `fix=false`, `gps_lost`, затем выход и `gps_ok` | «📡 пропал сигнал GPS» + карта, потом «🛰 GPS восстановлен» + карта |
| `still` | Стоит на месте, `still` с `still_min=10`, затем напоминание `still_min=40` | «🧍 нет движения 10 мин» + карта. Напоминание придёт, если с прошлого прошло больше `COOLDOWN_STILL_MIN` |
| `sos` | SOS, повтор того же пакета (имитация потерянного ответа), потом позиции в режиме SOS | Одно сообщение «🆘 SOS!» с кнопкой «✅ Принял» и живая карта, которая двигается |
| `offline` | Связь пропадает, пакеты и событие `still` копятся, затем досылаются (`--shuffle` — вперемешку) | «⚠️ не выходит на связь», затем «✅ связь восстановлена» и «🧍 … ⏳ получено с задержкой» |
| `errors` | Неверный токен, неверная подпись, битый JSON, широта 200°, дубликат | Ничего. В выводе симулятора коды 401/401/400/422/200/200 dup |
| `battery` | Разряд: `batt_low`, `batt_crit`, глубокий сон, зарядка | «🪫 низкий заряд», «🔴 критический разряд», «⚠️ не выходит на связь… вероятно, выключилась», «✅ связь восстановлена» |
| `serve` | Бесконечная ходьба до `Ctrl+C`. Удобно, чтобы вручную пробовать `/where` | Ответы на `/where` |
| `all` | Все сценарии подряд (по умолчанию) | Всё перечисленное |

Флаги:
- `--period 3` — свой период вместо полученного от сервера;
- `--shuffle` — досылать накопленное в случайном порядке;
- `--crit-sleep 20` — сколько секунд молчать после `batt_crit` (по умолчанию 5 периодов).

**Рецепт полной демонстрации за 3 минуты** (три окна терминала):

```bash
# окно 1: быстрые настройки, чтобы всё случилось за минуты, а не часы
#   в .env: DRY_RUN=true, MONITOR_INTERVAL_S=1, COOLDOWN_STILL_MIN=0, SOS_REMIND_S=20
python -m cane_server.cli add-device cane-01 --name "Трость Ивана" --period 3 --sim-config sim/cane-01.json
python -m cane_server

# окно 2: сопровождающие
python -m cane_server.devchat 1001 "/bind КОД" --name Мария
python -m cane_server.devchat 1001 "/invite"
python -m cane_server.devchat 1002 "/bind КОД-ИЗ-INVITE" --name Пётр

# окно 3: устройство
python -m simulator --config sim/cane-01.json --scenario all --shuffle
```

Логи такого прогона лежат в `reports/e2e-dry-run-server.log` и `reports/e2e-dry-run-simulator.log`.

## 8. Как пользоваться ботом

Найдите бота по username и нажмите **Start**. Пока чат не привязан к трости, бот отвечает только на
`/start`, `/help` и `/bind`. На остальные команды он предлагает привязаться.

### `/start`, `/help` — приветствие и список команд

```
Здравствуйте! Я бот умной трости. Сообщаю о тревогах и показываю, где находится человек с тростью.

Команды
/bind КОД — привязаться к трости по коду из паспорта изделия
/where — где сейчас трость (последняя позиция + запрос свежей)
...
Чтобы начать, отправьте /bind и код из паспорта трости, например: /bind ABCD-EFGH
```

### `/bind КОД` — привязка

Регистр и дефис не важны: `/bind hzqs75pe` тоже сработает.

```
✅ Вы привязаны к трости «Трость Ивана». Сопровождающих у трости: 1.
Теперь вам будут приходить тревоги. Попробуйте /where или /status.
```

Возможные отказы:
- «❌ Код не найден»;
- «❌ Этот код уже использован…» (одноразовый код уже потрачен, попросите `/invite`);
- «❌ Срок действия кода истёк»;
- «⛔ Слишком много неверных попыток. Повторите через 60 мин.»

Уже привязанные сопровождающие получают «👤 К трости «Трость Ивана» подключился новый сопровождающий: Пётр.»

### `/invite` — код для второго сопровождающего

```
🔑 Код приглашения для трости «Трость Ивана»: XJQP-C6XL
Действует до 08.10 01:27, только один раз.
Второй сопровождающий должен отправить боту: /bind XJQP-C6XL
```

### `/where` — где трость

Бот сразу присылает последнюю известную позицию и точку на карте, а у трости запрашивает свежую:

```
📍 Трость Ивана: последняя позиция 5 мин назад (01:22, спутников: 7).
Запросил свежую позицию — пришлю примерно через 30 с (после очередного выхода трости на связь).
[точка на карте]
```

Когда трость ответит (обычно в пределах одного периода):

```
📍 Свежая позиция: Трость Ивана (только что, 01:27).
[точка на карте]
```

Особые случаи:
- Позиций ещё нет: «позиция пока неизвестна — трость ещё не передавала координаты», свежая придёт позже.
- Трость под крышей: «…ответила на запрос, но спутники сейчас не видны».
- Трость не ответила за 5 минут: «⌛ … не ответила на запрос позиции за 5 мин».
- Трость «молчит»: в ответе будет предупреждение, а запрос выполнится, когда связь вернётся.

## 9. Доступ для настоящего ESP32

ESP32 должен достучаться до сервера по сети, поэтому `127.0.0.1` в прошивке **не подойдёт**:
это адрес самого ESP32.

### 9.1. Локальная сеть (демонстрация)

1. Ноутбук с сервером и ESP32 подключаются к **одной** сети Wi-Fi. Удобно раздать точку доступа с телефона.
2. Узнайте IP ноутбука: `ipconfig` на Windows (строка «IPv4-адрес», например `192.168.43.120`),
   `ip addr` на Linux.
3. Проверьте, что в `.env` стоит `HOST=0.0.0.0`.
4. Откройте порт в брандмауэре Windows (PowerShell от администратора):

   ```powershell
   netsh advfirewall firewall add rule name="Cane server 8000" dir=in action=allow protocol=TCP localport=8000
   ```

5. Зарегистрируйте устройство с правильным адресом:
   `python -m cane_server.cli add-device cane-01 --name "Трость Ивана" --server-url http://192.168.43.120:8000`.
   Тогда в `secrets.h` попадёт `CANE_SERVER_URL "http://192.168.43.120:8000/api/v1/telemetry"`.
6. Проверьте с телефона в той же сети: `http://192.168.43.120:8000/api/v1/health`.

Для работы бота ноутбуку нужен интернет, чтобы обращаться к Telegram. Раздача с телефона его обеспечивает.

**Через GSM (SIM800L)** локальный адрес недоступен: модем выходит в интернет через оператора.
Для GSM нужен сервер с публичным адресом (п. 9.2).

### 9.2. VPS с HTTPS

Пример для Ubuntu 22.04/24.04 и домена `cane.example.ru`, A-запись которого указывает на IP сервера.

**1. Код и окружение**

```bash
sudo apt update && sudo apt install -y python3 python3-venv git
sudo useradd -r -m -d /opt/cane cane
sudo -u cane git clone <ваш-репозиторий> /opt/cane/server
cd /opt/cane/server
sudo -u cane python3 -m venv .venv
sudo -u cane .venv/bin/pip install -r requirements.txt
sudo -u cane cp .env.example .env
sudo -u cane nano .env      # BOT_TOKEN=..., DRY_RUN=false, HOST=127.0.0.1, PORT=8000
sudo -u cane .venv/bin/python -m cane_server.cli add-device cane-01 --name "Трость Ивана" --server-url https://cane.example.ru
```

При `HOST=127.0.0.1` сервер доступен только через обратный прокси, напрямую снаружи к нему не обратиться.

**2. Служба systemd** — `/etc/systemd/system/cane.service`:

```ini

After=network-online.target

[Service]
User=cane
WorkingDirectory=/opt/cane/server
ExecStart=/opt/cane/server/.venv/bin/python -m cane_server
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now cane
journalctl -u cane -f          # логи
```

**3. HTTPS через Caddy.** Caddy сам получает и продлевает сертификат Let's Encrypt.

```bash
sudo apt install -y caddy
```

`/etc/caddy/Caddyfile`:

```
cane.example.ru {
    reverse_proxy 127.0.0.1:8000
}

http://cane.example.ru {
    reverse_proxy /api/v1/* 127.0.0.1:8000
}
```

```bash
sudo systemctl reload caddy
sudo ufw allow 80,443/tcp
```

- По **Wi-Fi** ESP32 ходит на `https://cane.example.ru/api/v1/telemetry` (`WiFiClientSecure`).
- **SIM800L** современный TLS не поддерживает (раздел 7 архитектуры). Поэтому второй блок
  оставляет `http://cane.example.ru/api/v1/...` без перенаправления на HTTPS. Пакеты по GPRS
  защищены подписью HMAC: подделать или изменить их без секрета нельзя. Токен по HTTP передаётся
  открыто, но без секрета он бесполезен. Повтор перехваченного пакета не действует: такой `seq`
  уже принят.
- Отладочный `/dev/bot` на VPS выключен, потому что там `DRY_RUN=false`.

**Вариант с nginx** (сертификат через `certbot --nginx`):

```nginx
server {
    listen 80;
    server_name cane.example.ru;
    location /api/v1/ { proxy_pass http://127.0.0.1:8000; }
    location / { return 301 https://$host$request_uri; }
}
server {
    listen 443 ssl;
    server_name cane.example.ru;
    ssl_certificate     /etc/letsencrypt/live/cane.example.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/cane.example.ru/privkey.pem;
    location / { proxy_pass http://127.0.0.1:8000; }
}
```

Бот работает через long polling: сам опрашивает Telegram, поэтому входящие порты для него не нужны.

## 10. Раздел для разработчика прошивки: контракт API

### 10.1. Адрес и метод

```
POST {CANE_SERVER_URL}            обычно http(s)://<сервер>/api/v1/telemetry
```

`/api/v1/event` — полный синоним того же обработчика (на рис. 4 и 5 он назван так). Рекомендуется
слать всё на `/telemetry`.

### 10.2. Заголовки

| Заголовок | Значение |
|---|---|
| `Content-Type` | `application/json` |
| `X-Device-Token` | Токен из `secrets.h` (`CANE_TOKEN`) |
| `X-Signature` | `hex(HMAC-SHA256(key = CANE_HMAC_SECRET, message = тело запроса))`, 64 символа в нижнем регистре (верхний тоже принимается) |

### 10.3. Как считать HMAC

1. Сформируйте JSON и сериализуйте его **в строку** (например, `serializeJson(doc, body)`).
2. Подпишите **ровно эти байты**. Ключ — строка секрета как есть: 64 ASCII-символа,
   **не** декодированные из hex в 32 байта.
3. Отправьте в теле ту же самую строку. Если после подписи пересериализовать JSON, порядок полей
   или пробелы изменятся, и подпись не сойдётся.

ESP32 (Arduino, mbedTLS входит в ядро):

```cpp
#include <mbedtls/md.h>

String hmacSha256Hex(const char* key, const String& body) {
  uint8_t digest[32];
  mbedtls_md_context_t ctx;
  mbedtls_md_init(&ctx);
  mbedtls_md_setup(&ctx, mbedtls_md_info_from_type(MBEDTLS_MD_SHA256), 1);
  mbedtls_md_hmac_starts(&ctx, (const uint8_t*)key, strlen(key));
  mbedtls_md_hmac_update(&ctx, (const uint8_t*)body.c_str(), body.length());
  mbedtls_md_hmac_finish(&ctx, digest);
  mbedtls_md_free(&ctx);
  char hex[65];
  for (int i = 0; i < 32; i++) sprintf(hex + 2 * i, "%02x", digest[i]);
  return String(hex);
}

String body;
serializeJson(doc, body);
http.addHeader("Content-Type", "application/json");
http.addHeader("X-Device-Token", CANE_TOKEN);
http.addHeader("X-Signature", hmacSha256Hex(CANE_HMAC_SECRET, body));
int code = http.POST(body);
```

Для SIM800L: заголовки задаются через `AT+HTTPPARA="USERDATA","X-Device-Token: ...\r\nX-Signature: ..."`,
тело — через `AT+HTTPDATA`. Подписывать нужно ту же строку, что уходит в `HTTPDATA`.

Проверьте свою реализацию на эталоне. Для ключа `s3cret` и тела `{"seq":1}` (9 байт, без пробелов)
подпись должна быть такой:

```
63c42aa7cb12b8b8f8ddd18d325c916eaa51e352fac52fc5899c227a8db0cb11
```

Её же выдаёт `printf '%s' '{"seq":1}' | openssl dgst -sha256 -hmac s3cret`.

### 10.4. Тело запроса

```json
{
  "dev": "cane-01", "seq": 1042, "ts": 1791018000,
  "type": "pos", "fix": true,
  "lat": 55.755800, "lon": 37.617300,
  "sats": 8, "hdop": 1.2,
  "bat_v": 3.85, "bat_pct": 52,
  "net": "wifi", "rssi": -61, "buffered": false
}
```

| Поле | Тип | Обяз. | Допустимо | Смысл |
|---|---|---|---|---|
| `dev` | string | да | `[A-Za-z0-9_-]{1,32}`, равен id устройства | Должен совпадать с устройством, которому принадлежит токен, иначе 403 |
| `seq` | integer | да | 0 … 4294967295 | Порядковый номер пакета. **Храните счётчик в NVS (Preferences) и только увеличивайте**, в том числе после перезагрузки. Повтор `seq` сервер считает дубликатом |
| `ts` | integer или null | нет | unix-секунды UTC | Время из GPS (или NTP). Если времени ещё нет, шлите `null` или `0`: сервер подставит время приёма. Время раньше 2024 года или более чем на 10 минут в будущем тоже заменяется |
| `type` | string | да | `pos`, `sos`, `still`, `batt_low`, `batt_crit`, `gps_lost`, `gps_ok` | Тип пакета (таблица 7) |
| `fix` | bool | нет (false) | | Есть ли валидный фикс (≥ 4 спутников, HDOP ≤ 5) |
| `lat`, `lon` | number | при `fix=true` | −90…90, −180…180 | Координаты. При `fix=false` можно передать последние известные: они попадут в тревогу `gps_lost`, но не в историю |
| `sats` | integer | нет | 0…64 | Число спутников |
| `hdop` | number | нет | 0…99.9 | Точность |
| `bat_v` | number | нет | 2.5…5.0 | Напряжение АКБ, В |
| `bat_pct` | integer | нет | 0…100 | Заряд, % |
| `net` | string | нет | `wifi`, `gsm` | Через какой канал отправлено |
| `rssi` | integer | нет | −150…0 | Уровень сигнала, dBm (для SIM800L пересчитайте CSQ: `dBm = −113 + 2·CSQ`) |
| `buffered` | bool | нет (false) | | `true` для записей из OfflineBuffer |
| `still_min` | integer | нет | 0…1440 | **Только для `still`:** сколько минут человек не двигается. Это поле добавлено сверх документа, чтобы бот мог написать «нет движения N минут» |

Неизвестные поля сервер игнорирует, поэтому в новых версиях прошивки можно добавлять поля, не ломая сервер.

### 10.5. Когда какой `type` слать

| `type` | Когда (таблица 7) | Особенности |
|---|---|---|
| `pos` | Плановая позиция раз в `period_s`. В режиме SOS — раз в 15 с. По команде `locate_now` — немедленно | Сопровождающим не пересылается, сохраняется. Во время SOS двигает живую карту |
| `sos` | Удержание кнопки ≥ 2 с | Повторяйте **с тем же `seq`**, пока не придёт ответ 200. Дубликат не создаёт второго сообщения |
| `still` | Смещение < 25 м за 10 мин; напоминание через 30 мин | Передавайте `still_min` |
| `batt_low` | U < 3,60 В, один раз | |
| `batt_crit` | U < 3,45 В, затем глубокий сон | Сервер запомнит, что это последнее сообщение, и в тревоге о молчании напишет «вероятно, выключилась» |
| `gps_lost` | Нет фикса дольше 120 с | `fix=false`, можно с последними `lat`/`lon` |
| `gps_ok` | Фикс восстановлен | `fix=true` с координатами |

Тревогу «устройство молчит» прошивка не шлёт: её определяет сервер.

### 10.6. Ответ сервера

`200 OK`:

```json
{ "ack": 1042, "dup": false, "cmd": null, "cfg": { "period_s": 30 } }
```

| Поле | Что делать |
|---|---|
| `ack` | Равен `seq` принятого пакета. Удалите пакет из OfflineBuffer и прекратите повторы |
| `dup` | `true`, если такой `seq` уже был. Пакет тоже считается принятым: удалить и не повторять |
| `cmd` | `null` или `"locate_now"`. Получив `locate_now`, сразу прочитайте фикс GPS и отправьте внеочередной `pos` (рис. 6). Сервер повторяет команду в каждом ответе, пока не получит такой пакет (до 5 минут) |
| `cfg.period_s` | Период передачи. Если он изменился, примените его (меняется через CLI `set-period`) |

### 10.7. Ошибки и реакция прошивки

Тело ошибки: `{"error": "<код>", "detail": ...}`.

| HTTP | `error` | Причина | Что делать прошивке |
|---|---|---|---|
| 400 | `malformed_json` | Тело — не JSON | Ошибка прошивки: пакет **выбросить**, не повторять |
| 401 | `invalid_token` | Нет или неверен `X-Device-Token` | Пакет выбросить. Индикация ошибки. Токен сменён (`rotate-token`)? Нужна перепрошивка |
| 401 | `invalid_signature` | Нет `X-Signature` или подпись не совпала | Пакет выбросить. Проверьте п. 10.3 |
| 403 | `dev_mismatch` | `dev` не совпадает с токеном | Пакет выбросить |
| 403 | `device_disabled` | Устройство отключено администратором | Не слать. Можно реже повторять, например раз в 10 минут |
| 413 | `body_too_large` | Тело > 4096 байт | Пакет выбросить |
| 422 | `validation_error` | Поле вне диапазона или неверный тип. В `detail` указано поле | Пакет выбросить |
| 5xx, таймаут, нет сети | — | Сервер или сеть недоступны | Оставить в OfflineBuffer, повтор с паузой 5…60 с, переключение Wi-Fi → GSM |

Правило простое: **2xx — пакет доставлен, 4xx — пакет испорчен и повторять его бессмысленно,
5xx и сетевые ошибки — повторить позже.** Иначе один плохой пакет навсегда застрянет в начале
очереди OfflineBuffer.

### 10.8. Досылка накопленного

- Записи из OfflineBuffer отправляйте с `buffered: true`, с их **исходными** `seq` и `ts`.
- Отправляйте в хронологическом порядке, как требует документ. Сервер корректно примет и любой другой
  порядок: последнюю позицию он определяет по `ts`, а не по порядку прихода.
- Чтобы не слать 200 записей по одной через медленный GPRS, можно использовать пакетный эндпоинт:

  ```
  POST /api/v1/telemetry/batch          (те же заголовки, подпись по всему телу)
  {"packets": [ {...}, {...} ]}          до 50 пакетов, тело до 200 КБ
  ```

  Ответ:

  ```json
  {"results": [{"index":0,"seq":17,"status":"ok","error":null},
               {"index":1,"seq":18,"status":"dup","error":null},
               {"index":2,"seq":19,"status":"rejected","error":[{"field":"lat","message":"..."}]}],
   "cmd": null, "cfg": {"period_s": 30}}
  ```

  Записи со статусами `ok`, `dup` и `rejected` удаляйте из буфера. Если весь запрос завершился ошибкой
  5xx или сеть недоступна, повторите его позже.

### 10.9. Примеры curl

Bash (Linux, macOS, Git Bash). Значения подставьте из вывода `add-device`:

```bash
TOKEN='6t8N5Rge9qSNbTeZyN1f1PvG_d0HICZP'
SECRET='a073f9961a81c9c1e3d5fd5cb96c9938ffc8cc37a46f9f39a19bdf47780c1c6d'
URL='http://127.0.0.1:8000/api/v1/telemetry'

send() {
  local sig
  sig=$(printf '%s' "$1" | openssl dgst -sha256 -hmac "$SECRET" | sed 's/^.* //')
  curl -s -X POST "$URL" -H 'Content-Type: application/json' \
       -H "X-Device-Token: $TOKEN" -H "X-Signature: $sig" --data-binary "$1"
  echo
}

send '{"dev":"cane-01","seq":101,"ts":null,"type":"pos","fix":true,"lat":59.957155,"lon":30.308288,"sats":8,"hdop":1.2,"bat_v":3.85,"bat_pct":52,"net":"wifi","rssi":-61,"buffered":false}'
send '{"dev":"cane-01","seq":102,"type":"sos","fix":true,"lat":59.9572,"lon":30.3084,"bat_v":3.84,"bat_pct":51,"net":"gsm","rssi":-79}'
send '{"dev":"cane-01","seq":103,"type":"still","fix":true,"lat":59.9572,"lon":30.3084,"still_min":10}'
send '{"dev":"cane-01","seq":104,"type":"gps_lost","fix":false,"lat":59.9572,"lon":30.3084,"sats":2}'
send '{"dev":"cane-01","seq":105,"type":"gps_ok","fix":true,"lat":59.9573,"lon":30.3085,"sats":7}'
send '{"dev":"cane-01","seq":106,"type":"batt_low","fix":true,"lat":59.9573,"lon":30.3085,"bat_v":3.58,"bat_pct":14}'
send '{"dev":"cane-01","seq":107,"type":"batt_crit","fix":true,"lat":59.9573,"lon":30.3085,"bat_v":3.44,"bat_pct":5}'
send '{"dev":"cane-01","seq":101,"type":"pos","fix":false}'
```

Ожидаемые ответы: `{"ack":101,"dup":false,...}` и так далее; последний запрос вернёт `"dup":true`.

Пример ошибки (неверная подпись):

```bash
curl -s -X POST "$URL" -H 'Content-Type: application/json' -H "X-Device-Token: $TOKEN" \
     -H 'X-Signature: 00' --data-binary '{"dev":"cane-01","seq":200,"type":"pos"}'
# {"error":"invalid_signature","detail":"Подпись HMAC не совпадает с телом запроса"}
```

PowerShell:

```powershell
$Token  = '6t8N5Rge9qSNbTeZyN1f1PvG_d0HICZP'
$Secret = 'a073f9961a81c9c1e3d5fd5cb96c9938ffc8cc37a46f9f39a19bdf47780c1c6d'
$Body   = '{"dev":"cane-01","seq":301,"type":"pos","fix":true,"lat":59.957155,"lon":30.308288}'
$Hmac   = [System.Security.Cryptography.HMACSHA256]::new([Text.Encoding]::UTF8.GetBytes($Secret))
$Sig    = -join ($Hmac.ComputeHash([Text.Encoding]::UTF8.GetBytes($Body)) | ForEach-Object { $_.ToString('x2') })
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/api/v1/telemetry' -ContentType 'application/json' `
  -Headers @{ 'X-Device-Token' = $Token; 'X-Signature' = $Sig } -Body $Body
```

## 11. Частые проблемы и решения

| Симптом | Причина и решение |
|---|---|
| `ConfigurationError: BOT_TOKEN не задан` | Укажите `BOT_TOKEN` в `.env` или включите `DRY_RUN=true`. Запускайте из корня проекта, иначе `.env` не найдётся |
| `Telegram отклонил BOT_TOKEN` | Токен скопирован с ошибкой или отозван. Получите новый у @BotFather (`/token`) |
| `TelegramConflictError: terminated by other getUpdates request` | С тем же токеном запущен второй экземпляр (другой ноутбук, VPS). Оставьте один |
| Бот молчит в Telegram | Сервер не запущен, или `DRY_RUN=true` (в этом режиме Telegram не используется). Посмотрите лог |
| Бот отвечает «Вы пока не привязаны…» | Выполните `/bind КОД`. Код можно перевыпустить: `cli new-code cane-01` |
| «Код уже использован» | Код одноразовый. Второму сопровождающему нужен `/invite` от первого |
| «Слишком много неверных попыток» | Подождите `BIND_BLOCK_MIN` минут |
| В Git Bash `devchat 1001 "/where"` даёт «Не понимаю это сообщение» | Git Bash превращает `/where` в путь `C:/Program Files/Git/where`. Запустите `export MSYS_NO_PATHCONV=1` или используйте PowerShell/cmd |
| Устройство получает 401 `invalid_signature` | Подписываются не те байты, что отправляются; ключ декодирован из hex; JSON пересериализован после подписи. См. п. 10.3 и эталон |
| Устройство получает 401 `invalid_token` | Опечатка в токене, или выполнен `rotate-token`. Возьмите актуальные данные |
| Устройство получает 422 | В `detail` указано поле и причина: например, `lat` вне диапазона или `fix=true` без координат |
| ESP32 не может подключиться | В прошивке указан `127.0.0.1`/`localhost` вместо IP ноутбука; брандмауэр закрыл порт; ESP32 и ноутбук в разных сетях (гостевая сеть изолирует клиентов) |
| Тревога «не выходит на связь» приходит слишком часто | Увеличьте `SILENCE_PERIODS` или период устройства (`cli set-period`). Порог равен `SILENCE_PERIODS × period_s` |
| Не приходит повторное «нет движения» | Сработал антифлуд: повтор не чаще `COOLDOWN_STILL_MIN`. В логе будет «не отправлено: cooldown» |
| Время в сообщениях сдвинуто | Настройте `DISPLAY_TZ`. На Windows нужен пакет `tzdata`, он есть в requirements |
| `Address already in use` / порт занят | Смените `PORT` или остановите другой процесс |
| `database is locked` | Одну базу открыли два процесса сервера. Запускайте один экземпляр. CLI можно запускать параллельно с сервером |
| Telegram недоступен из сети (блокировка) | Сервер продолжит принимать данные, а сообщения будут ждать в очереди и уйдут при восстановлении (до `OUTBOX_MAX_ATTEMPTS` попыток). Для постоянной работы разместите сервер на VPS |
| Как всё сбросить | Остановите сервер и удалите `data/cane.db*` (и `sim/*.seq.json` для симулятора) |
